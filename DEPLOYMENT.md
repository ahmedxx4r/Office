# Deploy Office with GitHub + Vercel

## Hosting layout
- **Vercel:** React/Vite/Three.js frontend. Git integration deploys pushes to `main` automatically and creates Preview deployments for branches/PRs.
- **Render:** persistent Express + Socket.IO API and BullMQ worker (`render.yaml` Blueprint).
- **PostgreSQL:** Supabase or another managed PostgreSQL provider.
- **Redis:** Upstash or another managed Redis provider with TLS.

Do not deploy the Express/BullMQ process as a static Vercel output. The queue worker and Socket.IO server require a persistent process.

## 1. GitHub
Repository: `ahmedxx4r/Office`, production branch: `main`.

## 2. Provision managed data services
Create a PostgreSQL database and a Redis database. Keep their connection strings server-side:
- `DATABASE_URL`
- `REDIS_URL`

Never put these in frontend `VITE_*` variables or commit them to Git.

## 3. Deploy the persistent API on Render
Create a Blueprint from `ahmedxx4r/Office`. Render reads `render.yaml` and proposes `office-api`. Choose an always-on instance for dependable background work.

Set:
- `DATABASE_URL`
- `REDIS_URL`
- `OWNER_PASSWORD` (strong password)
- `OPENAI_API_KEY` (optional; without it the app uses demo/fallback behavior)
- `CLIENT_ORIGIN` (exact Vercel production origin, set after first frontend deployment)

`AUTH_SECRET` is generated by the Blueprint.

Verify `https://YOUR-API-HOST/api/health`.

## 4. Vercel Git project
- Import GitHub repository `ahmedxx4r/Office`
- Project name: `office`
- Team: Nexlova
- Root Directory: `.`
- Framework: Vite
- Install Command: `npm install`
- Build Command: `npm run build`
- Output Directory: `client/dist`

Add in Production, Preview and Development:
- `VITE_API_URL` = `https://YOUR-API-HOST` (no trailing slash)
- `VITE_SOCKET_URL` = `https://YOUR-API-HOST` (no trailing slash)

Git integration deploys pushes to `main` automatically.

## 5. CORS
After Vercel creates the production URL, set Render's `CLIENT_ORIGIN` to that exact origin. Add any custom domain origins explicitly, comma-separated. Redeploy/restart the API.

## 6. Verify
1. Open Vercel URL and sign in with `OWNER_PASSWORD`.
2. Verify `/api/state` returns 200.
3. Confirm Socket.IO connects.
4. Create a test task and verify it reaches Needs Review.
5. Approve it and verify Completed.
6. Check Render logs and `/api/health`.

## 7. CI
`.github/workflows/ci.yml` runs server tests and frontend production build on pushes to `main` and pull requests. Vercel Git integration handles deployments separately.

## Important
The repository is connected to Vercel for frontend deployment only once the Vercel Git project is created. Render, PostgreSQL, and Redis still require provisioning and environment variables. Do not treat frontend deployment as proof that autonomous background agents are running.
