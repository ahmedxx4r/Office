# Deploy `office` with GitHub + Vercel

## Hosting layout

- **Vercel:** React/Vite/Three.js frontend; Git integration provides Preview deployments for branches/PRs and Production deployments from `main`.
- **Render:** persistent Express + Socket.IO API and BullMQ worker (`render.yaml` Blueprint included).
- **PostgreSQL:** Supabase or another managed PostgreSQL provider.
- **Redis:** Upstash or another managed Redis provider with TLS support.

Do not deploy the Express/BullMQ process as a static Vercel output. The queue worker and Socket.IO server require a persistent process. The Vercel deployment is the browser-facing office; its API URL points to the persistent API service.

## 1. Create and push the GitHub repository

Create a GitHub repository named **office** (empty repository; do not add a second README or license). From the project root:

```powershell
git init
git add .
git commit -m "Initial ISystem"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/office.git
git push -u origin main
```

Replace `YOUR_GITHUB_USERNAME` with your GitHub username. If the folder is already a Git repository, do not run `git init` again; inspect `git status` and `git remote -v` first.

## 2. Provision managed data services

Create:

- A PostgreSQL database. Save its server-side connection string as `DATABASE_URL`.
- A Redis database with TLS. Save its connection string as `REDIS_URL`.

Do not put either connection string in frontend `VITE_*` variables or commit them to Git.

## 3. Deploy the persistent API and worker on Render

1. In Render, create a **Blueprint** from GitHub repository `office`.
2. Render reads `render.yaml` and proposes the `office-api` Node web service.
3. Review the plan/price and choose an always-on instance appropriate for your expected workload. Do not use a sleeping service for dependable background execution.
4. Add the following secret environment variables in Render:
   - `DATABASE_URL`
   - `REDIS_URL`
   - `OWNER_PASSWORD` — strong owner password
   - `OPENAI_API_KEY` — optional for live model responses; without it the app uses demo/fallback behavior
   - `CLIENT_ORIGIN` — the exact Vercel production URL; update after the first frontend deployment
5. `AUTH_SECRET` is generated by the Blueprint. Keep it private.
6. Wait for the service to deploy and check `https://YOUR-API-HOST/api/health`.

The service must remain running. Its API and Socket.IO share the same public origin.

## 4. Connect the GitHub repository to Vercel

1. In Vercel, choose **Add New → Project** and import `YOUR_GITHUB_USERNAME/office`.
2. Select the intended team (the Nexlova team if this project belongs there).
3. Project name: `office`.
4. Root Directory: `.` (repository root; do not select `client`).
5. Framework: Vite (auto-detected; `vercel.json` also configures it).
6. Build command: `npm run build`.
7. Output directory: `client/dist`.
8. Install command: `npm install`.
9. Add these environment variables for **Production, Preview and Development**:
   - `VITE_API_URL` = `https://YOUR-API-HOST` (no trailing slash)
   - `VITE_SOCKET_URL` = `https://YOUR-API-HOST` (no trailing slash)
10. Deploy the project.

Vercel Git integration will deploy pushes to the configured production branch (normally `main`) automatically. Pull requests and non-production branches receive Preview deployments according to the Git integration settings.

## 5. Finish CORS configuration

After Vercel gives the project its production URL, set Render's `CLIENT_ORIGIN` to that exact origin, e.g. `https://office-YOUR-TEAM.vercel.app`. If you use a custom domain, include the exact origin(s), comma-separated. Restart/redeploy the API after changing it.

## Owner-only access
The React app displays an owner sign-in screen when the API reports that authentication is required. Set `OWNER_PASSWORD` on the API service before sharing the Vercel URL. The API validates signed sessions, and Socket.IO rejects unauthenticated connections. Do not store the password in source files or `VITE_*` variables.

## 6. Verify the live app

1. Open the Vercel URL.
2. Sign in with `OWNER_PASSWORD`.
3. Confirm employee state loads from the API.
4. Open browser DevTools → Network and verify `/api/state` returns 200.
5. Confirm Socket.IO connects to the API host.
6. Create a test task and verify it moves from **Queued** to **In Progress** to **Completed**.
7. Check Render logs and `/api/health` for database and queue mode.

## 7. Continuous integration

`.github/workflows/ci.yml` runs server tests and the frontend build on pushes to `main` and pull requests. Vercel Git integration performs the deployment separately. A green CI check does not replace checking the live API/database/Redis configuration.

## Local development

```powershell
npm install
Copy-Item server/.env.example server/.env
docker compose up -d postgres redis
npm run dev
```

Vite proxies `/api` and `/socket.io` to `localhost:4000` when `VITE_API_URL` and `VITE_SOCKET_URL` are empty.
